Fence Redis queue claims with a per-claim token. The in-flight set used the raw message as its member, so a stalled execution whose claim had expired and been redelivered would, on finishing, remove the redelivered claim's deadline. A crash during the redelivery then lost the job, and the stale execution could also schedule a retry, release the enqueue dedup key, or fail the run underneath the live claim. Each claim now splices a unique token into its in-flight member, and ack, retry, 503 delay, and dead-letter settle through one atomic script that does nothing unless the claim still exists. A stale execution only updates its local completed cache and logs at debug. A claim that expires before its settle now increments a per-message reclaim counter, and the redelivery counts those reclaims as attempts, so a delivery that keeps outliving its visibility deadline dead-letters and fails the run instead of redelivering forever. Claiming is itself one script now, so an item can no longer land in the in-flight set after the startup recovery requeued it. A successful settle releases the enqueue dedup key only while it still holds that message's id, so a stalled execution whose success arrived late no longer leaves the key to expire on its own. Rolling deploys are safe: legacy untokened in-flight members are still promoted, and tokened members promoted by an older worker still parse as envelopes and are normalized on delivery.
